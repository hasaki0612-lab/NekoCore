# 命令与权限

[English](../en/COMMANDS.md) | [返回 README](../../README.md)

这一页分三部分：玩家会用到的命令、管理员命令（含使用场景和例子）、以及完整的权限节点表。

先给一条不需要记的捷径：**大部分玩家命令都可以从 `/menu` 点进去。** 面板里有签到、任务、商店、Bag、资料卡和世界跳转的入口。所以你不必要求玩家背命令——这一页更多是给你自己看的。

---

## 玩家命令

### 日常循环

这五条命令构成了玩家每天的主要操作。

| 命令 | 做什么 |
| --- | --- |
| `/menu` | 打开服务器面板 |
| `/checkin` | 领取今天的签到奖励 |
| `/coins` | 看看自己有多少金币 |
| `/sethome` | 把当前位置记成当前世界的小窝 |
| `/home [worldName]` | 回小窝 |

`/menu` 是入口。面板里能直接看到自己的资料卡（等级、经验、金币、游玩时长、首次加入时间）、今天的九个任务、签到状态，还有一个"显示网络地区"的隐私开关。

`/coins` 看起来多余，但它有个实际用途：玩家在商店里花完钱之后会想知道余额，而打个命令比开面板快。

**关于 Home：** `/sethome` 是**按世界分开记的**。玩家在主世界设一个、下界设一个、末地设一个，三个互不覆盖。`/home` 不带参数就回当前世界的家；带世界名可以跨世界回去（前提是那个世界已加载）。

```text
/home
/home world
/home world_nether
```

**什么时候会失败：** 世界名拼错了、大小写不对、或者那个世界没加载，都会得到一句"暂时找不到这个世界"。玩家来回切换世界的时候，正在进行的传送会被取消——这是防止把玩家送到错误位置。

### 想确认自己家在哪

```text
/check home <worldName>
```

例子：

```text
/check home world
```

输出类似：

```text
world 的 Home · 128, 65, -340 （朝向 90.0 / 0.0）
```

**这条命令的用处比看起来大。** 玩家经常会遇到"我明明设过家但怎么回不去"——通常是设在了错误的世界，或者当时的坐标已经不安全了。`/check` 能让他们自己先确认一遍，不用来找你。

### 商店与随身仓库

| 命令 | 做什么 |
| --- | --- |
| `/store` | 打开日常商店 |
| `/bag` | 打开随身 Bag |

商店的交互是**右键买入、左键出售**。数量可以从预设里选，也可以在聊天框里自己填。填数字的那条输入**不会发给其他玩家**——它只在插件内部传递。

**只认普通的左键和右键。** 按住 Shift 的左/右键、中键、数字键交换都不会有反应。这是刻意的：交易会真的扣钱和给物品，不希望误触触发。

Bag 是一个跨世界跟着玩家的物品容器。默认只在主世界允许取放，其他世界只读。

### 和朋友汇合

| 命令 | 做什么 |
| --- | --- |
| `/tpn <玩家名>` | 请求传送到某位在线玩家身边 |
| `/yes` | 接受一个收到的传送请求 |
| `/no` | 婉拒一个收到的传送请求 |

```text
/tpn Yuki
```

对方会收到一条请求，60 秒内可以用 `/yes` 回应。接受之后，请求方会被送到"对方接受请求时所在的位置附近"，而不是一个实时跟随着对方的位置——这个小细节避免了对方一边跑一边接受导致的诡异落点。

**几个设计选择值得知道：**

- 传送是**双向同意**的。不是"点一下就过去"，被传的人有决定权。
- 发起方有冷却时间，默认 180 秒。这个数字可以通过头衔权益缩短。
- 有一方离线了，请求自动取消。
- 插件重载配置的时候，进行中的请求会被取消，而不是拿半新半旧的规则继续处理。

## 管理命令

所有管理命令都在 `/nekocore` 下面，需要 `nekocore.admin` 权限（默认只有 OP）。

不记得有哪些子命令的时候，直接打 `/nekocore`，会把用法列表发给你。

### 配置相关

#### `/nekocore config check`

**验证磁盘上的配置文件，但不应用任何改动。**

这是改完 YAML 之后应该**先**跑的那条命令。它会完整地解析和验证所有配置，报告问题，然后把结果丢给你，什么也不改。

**什么时候用：**

- 你刚改完 `config.yml`，想知道有没有写错，但还没决定要不要生效；
- 你在正式服上改了一个不太确定的值，想先确认语法和取值范围；
- 你在排查一个问题，想排除"配置本身不合法"这个可能。

输出要么是"配置检查通过；没有应用任何改动"，要么是一条带 YAML 路径的错误。

#### `/nekocore reload`

**解析 → 验证 → 构建完整的新配置 → 成功后整体切换。**

和 `config check` 用的是同一套验证逻辑，区别只有一个：通过之后它会真的生效。

**它和 `config check` 的区别，值得记一下：**

| | 做什么 | 什么时候用 |
| --- | --- | --- |
| `config check` | 只验证，什么都不改 | 刚改完 YAML，想先确认没写错 |
| `reload` | 验证通过后整体切换 | 确认没问题了，要让它生效 |

**`reload` 是原子的。** 所有配置全部通过之后才会替换。任何一项失败，服务器继续用旧的有效配置运行，并且告诉你错在哪个路径、期望什么类型。不会出现"一半新一半旧"的状态。

**reload 覆盖不到的东西：** 更换 JAR、改数据库文件名、安装新插件、世界插件变更。这些要完整重启。

**成功之后会发生什么：** 计时类任务（Tips 的轮播、清理倒计时等）会重新开始计时。进行中的传送请求会被取消，避免用旧规则处理一半。

### 诊断

#### `/nekocore status`

显示 NekoCore、Paper、Java 的版本、数据库 schema，以及各个模块的状态：

- Store、Bag、Tasks、GeoIP、Mascot、AFK Pool、Weekly Leaderboard
- PlaceholderAPI 是否可用

**这一条命令能解决大部分"某功能没生效"的疑惑。** 遇到问题的第一反应应该是看它，而不是翻日志。

#### `/nekocore doctor`

`status` 的同义词。两个命令输出一样，用哪个看你顺手。（`doctor` 这个名字更适合"我出问题了，帮我看看"的心境。）

### 经济管理

```text
/nekocore coins add <player|UUID> <amount>
/nekocore coins set <player|UUID> <amount>
/nekocore coins take <player|UUID> <amount>
/nekocore exp add <player|UUID> <amount>
/nekocore exp set <player|UUID> <amount>
```

例子——给玩家补一笔活动奖励：

```text
/nekocore coins add Yuki 5000
```

玩家名和 UUID 都接受。**名字有歧义的时候**（比如历史上有两个同名的），插件会提示你改用 UUID。找不到的玩家会告诉你"还没有这位玩家的资料，请先让 TA 加入服务器"。

这些都是有日志的操作，改完余额会同时通知你和目标玩家。

### 商店管理

```text
/nekocore store refresh-enchants
/nekocore store status <player|UUID>
/nekocore store reset <player|UUID>
```

**`refresh-enchants`** —— 立刻换一批每日附魔书，同时重置本期的购买次数。

正常情况下一批书会在北京时间 04:00 自动更换，不需要手工干预。这条命令的用处是：你在测试或者刚改完附魔价格，想立刻看到新的一批。

**`status`** —— 看看某个玩家今天的商店额度用了多少。

排查"玩家说他买不了东西"的时候很有用：先看一眼是真的额度用完了，还是别的原因。

```text
/nekocore store status Yuki
```

**`reset`** —— 清空某个玩家的购买与出售限额。

**这条命令要慎用。** 它会直接绕过你设的每日限额，而限额是你防通胀的主要手段。合理的场景是：玩家遇到了一个 bug 导致额度被错误消耗；或者你在做活动，想让某些人不受限制。

### 每日任务管理

```text
/nekocore tasks status
/nekocore tasks reroll confirm
/nekocore tasks reset <player>
/nekocore tasks progress <player> <taskId> <amount>
```

**`status`** —— 列出今天抽出来的九个任务，带难度、task ID 和名字。

排查"为什么今天没有困难任务"或者确认某个任务有没有被抽中的时候用它。

**`reroll confirm`** —— 重新抽今天的一套任务。

注意那个 `confirm`：它是刻意的二次确认，因为重新抽取是有代价的——旧的 rotation 进度会被保留归档，新任务从 0 开始。玩家的已领取记录不受影响，但正在做的进度会作废。

适合的场景：你发现今天的某个任务因为配置错误无法完成，想让全服换一套。

**`reset <player>`** —— 清空某个玩家在当前任务轮换里的进度。

**`progress <player> <taskId> <amount>`** —— 手动把某个玩家的某个任务推进一步。

```text
/nekocore tasks progress Yuki hard_iron_golem 1
```

这条主要用于两种情况：玩家遇到了真实的计数 bug，你帮他补上；或者你在测试新配置的任务能不能正常计数。

如果填的 task ID 不在今天的轮换里，会得到一句"这个 task ID 不在今天的轮换中，先用 status 看看吧"——先跑 `status` 确认 ID。

### 其他

```text
/nekocore cleanup now
/nekocore levelshop open <player>
```

**`cleanup now`** —— 立刻清理一次地面掉落物，不等下一个清理周期。清理前的倒计时提醒照常会发给玩家。

**`levelshop open <player>`** —— 为指定玩家打开头衔小铺。

**注意：头衔小铺只有这一个入口。** 玩家自己没有打开它的命令，必须由管理员或控制台发起。这是有意设计的——头衔小铺被定位成"在特定地点提供"的功能，通常配合一个 NPC 或者大厅里的某个位置使用。

`levelshop.worlds` 限制了哪些世界允许打开，默认只有 `world`。玩家不在允许的世界时会提示回去找头衔 NPC。

## 权限节点

### 玩家权限

全部默认 `true`，也就是说普通玩家都有。

| 权限 | 对应命令 | 默认 |
| --- | --- | --- |
| `nekocore.menu` | `/menu` | `true` |
| `nekocore.coins` | `/coins` | `true` |
| `nekocore.checkin` | `/checkin` | `true` |
| `nekocore.home.set` | `/sethome` | `true` |
| `nekocore.home.use` | `/home` | `true` |
| `nekocore.home.check` | `/check home` | `true` |
| `nekocore.store` | `/store` | `true` |
| `nekocore.bag` | `/bag` | `true` |
| `nekocore.tpn` | `/tpn`、`/yes`、`/no` | `true` |
| `nekocore.levelshop` | 使用头衔小铺 | `true` |

**这几组权限是分开的**，所以你可以做细粒度的限制。比如：`nekocore.home.set: true` 但 `nekocore.home.use: false` 是没有意义的组合；但 `nekocore.tpn: false` 只禁传送请求、不影响其他功能，就很合理。

### 管理权限

| 权限 | 说明 | 默认 |
| --- | --- | --- |
| `nekocore.admin` | `/nekocore` 的全部子命令 | `op` |

**这是唯一的 OP 权限节点。** 拿掉它，玩家就完全碰不到管理命令。

### 头衔权益权限

这三个默认 `false`，通过购买对应头衔获得。它们也可以被权限插件单独授予——如果你想做"VIP 直接送权益"这类设计，这是入口。

| 权限 | 作用 | 默认 |
| --- | --- | --- |
| `nekocore.perk.auto-checkin` | 上线自动签到 | `false` |
| `nekocore.perk.colored-chat` | 安全的聊天颜色 | `false` |
| `nekocore.perk.fast-tpn` | 更短的传送冷却 | `false` |

`config.yml` 的 `levelshop.permissions` 里可以改这三个节点的名字——如果你的服务器已经有一套权限命名规范，可以对齐过去。

**权益按已拥有的最高档位给。** 玩家买了 Neko 之后换戴 Yuki 的外观，传送冷却仍然是 Neko 的 30 秒。所以手动授予 `nekocore.perk.fast-tpn` 给一个没买头衔的玩家，效果等同于他拥有了那个权益。

## 关于管理员权限的几句

`nekocore.admin` 是一个**很宽的权限**。拿到它的玩家可以：

- 直接给自己或者别人加金币和等级；
- 重置商店限额；
- 重抽任务、推进任务进度；
- 重载配置。

这些操作里有些是不可逆的（加出去的金币不会自动收回），有些会改变全服状态（重抽任务影响所有人）。

所以：

- **不要把这个权限交给不受信任的玩家。** 如果有玩家需要一部分管理能力，用别的插件给他更窄的权限，而不是 `nekocore.admin`。
- **控制台天然拥有全部管理能力**，所以涉及敏感操作的维护动作建议直接在控制台做，而不是给自己 OP 之后在游戏里做。
- **涉及玩家 GUI 或传送的命令要在游戏内执行**——比如 `levelshop open`，控制台虽然能跑，但打开的是玩家的界面，这是可以工作的。而 `/menu`、`/sethome` 这类命令需要有一个玩家身份，控制台执行只会得到一句"请在游戏里使用这个功能"。

权限配置的更多安全建议见[安全策略](../../SECURITY.md)。
