# 兼容性与常见问题

[English](../en/COMPATIBILITY.md) | [返回 README](../../README.md)

前半页讲兼容范围——NekoCore 在什么样的环境里被验证过、什么样的环境里不保证。后半页是问答，把最常被问到的问题按"为什么会出现"和"按什么顺序排查"写清楚。

遇到问题的时候，建议按这个顺序动手：**`/nekocore status` → 看控制台日志 → 查本文对应的问题 → `/nekocore config check`**。九成的情况在前两步就能定位。

---

## 兼容范围

### 明确被验证的

| 组件 | 版本 |
| --- | --- |
| Paper | 26.2（API build 129 stable） |
| Java | 25 |

### 声明支持的缺失组件行为

下面这些组件**缺失时应该安全降级**——也就是说，装不装都不影响核心功能：

| 组件 | 缺失时的表现 |
| --- | --- |
| PlaceholderAPI | 只跳过占位符集成 |
| Citizens | 只禁用 Mascot 模块 |
| Multiverse-Core | 已加载的主世界回退到 Paper 世界出生点 |
| GeoLite2 MMDB | 只禁用网络地区显示 |

### 没有声明的

| 平台 | 状态 |
| --- | --- |
| Spigot / CraftBukkit | 未测试，不声明支持 |
| Folia | 未测试，不声明支持 |
| 未来的 Paper 版本 | 大概率可用，但未测试 |
| 跨服网络（BungeeCord 等） | 不在设计目标内 |

### 可以共存但不保证的

**WorldGuard** 和 **Multiverse-Inventories** 不是 NekoCore 的依赖，也没有出现在 `depend` 或 `softdepend` 里。它们可以和 NekoCore 跑在同一个服务器上，但**共存场景不在自动测试的保证范围内**。

具体来说，值得你自己在测试服验证的组合：

- WorldGuard 的区域保护与 NekoCore 的传送、Bed Home 是否互相干扰；
- Multiverse-Inventories 的独立背包与 NekoCore 的 Bag 规则是否冲突（Bag 的 `writable-worlds` 白名单就是为这个场景准备的）；
- 死亡/重生规则被其他插件接管之后，NekoCore 的死亡坐标提示是否还准确。

**自动测试用模拟对象覆盖了插件契约和降级路径，但它无法替代真实服务器上的插件组合测试。** 这句话是认真的，不是免责声明式的客套。

### 显示所有权的冲突

这一类问题值得单独提前知道，因为它是最难自己诊断的：

**TAB 列表、NameTag（头顶名字）和聊天前缀，在技术上只能有一个"所有者"。** 两个插件同时往同一个地方写内容时，屏幕上显示什么取决于**谁后写**——而这个顺序在重启之后可能变化。

所以表现出来的现象常常是"有时候正常有时候不正常"，让人以为是随机 bug。

**解决办法是明确选一边：**

- 用 NekoCore 的 TAB → 关掉其他 TAB 插件；
- 用别的 TAB 插件 → 设 `tab.enabled: false`，需要 NekoCore 数据就装 PlaceholderAPI 用 `%nekocore_*%`；
- 用了别的聊天插件显示前缀 → 设 `chat.level-prefix-enabled: false`，避免前缀出现两次。

## 常见问题

### 为什么 TAB 没显示？

TAB 完全不出现，或者显示成空白/默认样式。

**按顺序排查：**

1. **`/nekocore status`**，看 TAB 这一项是不是启用状态。如果 `tab.enabled` 是 `false`，或者配置重载失败导致还在用旧配置，这里能看出来。
2. **确认没有第二个 TAB 插件在抢。** 这是最常见的原因。任何 TAB、计分板、列表类插件都可能和 NekoCore 争夺同一块显示区域。临时把其他 TAB 插件移走启动一次，如果 NekoCore 的 TAB 就正常了，那就是所有权冲突。
3. **检查 `messages.yml` 的 `tab.header` / `tab.footer`。** 如果你编辑过这两段多行文本，缩进或者 `|-` 标记写坏了，内容可能变成空。用 `/nekocore config check` 验证。
4. **看 `tab.refresh-seconds`。** 默认 1 秒。设成很大的值（比如 600）会让 TAB 看起来像卡住了。
5. **确认 Paper 版本是 26.2。** 更新或更旧的 Paper 上 TAB 的行为没有保证。

**一个容易忽略的点：** TAB 的刷新是**全服共用一个任务**，数据来自 Paper 和 NekoCore 的内存缓存，**不查询数据库**。所以 TAB 显示不出金币的时候，问题一般在配置或者显示所有权，而不是数据库。

### 为什么地区一直没有？

TAB 或聊天里应该出现 `[广东]` 这样的前缀，但是空的。

按这个顺序查，**前面几步能解决绝大多数情况**：

1. **`location-prefix.enabled` 是 `true` 吗？** 默认是 `false`，很多人忘了打开。
2. **重载或重启过了吗？** 你放了文件、改了配置之后，需要 `/nekocore reload`（或完整重启）才会真正读取。**只把文件拷进去是不会自动生效的**——这一步最容易被跳过。
3. **文件在对的位置吗？** 必须是 `plugins/NekoCore/GeoLite2-City.mmdb`，和 `config.yml` 同一个目录。**不是** `plugins/` 根目录，也不是 JAR 旁边。
4. **文件名大小写一致吗？** `config.yml` 里 `database-file` 写的是什么，磁盘上的文件名就得是什么。Linux 上大小写敏感。
5. **下的是 City 版吗？** Country 版没有省级数据，中国玩家会只显示国家甚至什么都显示不出来。要 `GeoLite2-City`。
6. **解压了吗？** 从 MaxMind 下载到的是 `.tar.gz`，需要解出里面的 `.mmdb`。直接把压缩包改名放进去是读不出来的。
7. **玩家自己的隐私开关关了吗？** `/menu` 里有个"显示网络地区"，玩家自己关掉之后就不会显示。这是有意设计的功能，不是 bug。
8. **`tab.show-location-prefix` 是 `true` 吗？** 这个全局开关和玩家的个人开关是**两套独立**的控制，两个都开才会显示。
9. **有别的 TAB 插件在覆盖吗？** 见上一个问题。

**如果都排除了还是不显示：** 临时把 `advanced.debug` 设成 `true` 再启动一次，看详细的异常信息。默认情况下缺失或损坏的 MMDB 只会让 GeoIP 安静地停用，不会刷一大段堆栈——这是为了不吓到人，但也意味着你需要主动打开 debug 才能看到细节。

完整的安装与隐私说明见 [GeoIP 文档](GEOIP.md)。

### 为什么 Mascot 点了没反应？

右键 NPC 什么都不发生。

**按顺序排查：**

1. **`/nekocore status`** 里 Mascot 是什么状态？如果是禁用，说明 Citizens 没被检测到，或者 `mascot.enabled` 是 `false`。
2. **Citizens 装了吗？版本和 Paper 26.2 兼容吗？** Citizens 的更新节奏和 Paper 不完全同步。不兼容的时候 NekoCore 只会安静地禁用 Mascot，日志里可能有一条 warning。
3. **NPC 真的 spawn 了吗？** 在 Citizens 里创建不等于已经放置在世界上。
4. **`npc-id` 对吗？** 站到 NPC 旁边执行 `/npc id`，那个数字必须和 `config.yml` 里 `mascot.npc-id` 完全一致。
5. **是用主手右键的吗？** 副手交互不触发。
6. **是不是点了太快？** 15 秒内超过 5 次会切到"超限回复池"，回复的语气会变（"慢一点啦"），并且有 2 秒的冷却。如果 `messages.yml` 里的 `over-limit-replies` 被改空了，这时候就不会有任何输出——看起来就像"点了没反应"。
7. **重启过了吗？** 装 Citizens 属于新增插件，需要完整重启。

**再提醒一次那条边界：** NekoCore 不创建、不重命名、不移动也不换皮任何 NPC。如果 NPC 本身有问题，那要在 Citizens 里解决。

配置细节见[配方手册的 Mascot 一节](RECIPES.md#我想加一个-citizens-吉祥物)。

### 为什么排行榜没有出现？

金币周榜应该在某个坐标显示一块悬浮文字牌，但是那里什么都没有。

**按顺序排查：**

1. **两个开关都是 `true` 吗？** `weekly-coin-leaderboard` 需要 `enabled: true` **和** `position-configured: true` **同时**成立。这是刻意的双门闩，防止在没有确定坐标的时候乱生成东西。
2. **世界加载了吗？** `world` 字段写的世界必须在服务器上实际加载。
3. **坐标那里有空间吗？** 牌子生成在实心方块内部是看不见的。
4. **本周真的有金币记录吗？** 榜单统计的是**本周的金币收入**，不是当前余额。如果这一周还没有人赚过钱，榜单是空的（会显示"本周还没有金币记录"）。
5. **`position-configured: false` 的时候看日志。** 这种情况下统计**照常进行**，只是不生成显示，并且插件会记一条 WARNING 提醒你。所以你可能是"开着 `enabled` 但忘了填坐标"。
6. **重启或重载过了吗？**

**关于 0,0,0：** NekoCore **默认绝不会在 `0,0,0` 生成任何东西**。配置里的 `x: 0.0, y: 0.0, z: 0.0` 是占位值，配合 `position-configured: false` 使用。如果你在 0,0,0 看到了东西，那是别的插件放的。

**一条边界：** NekoCore 只管理带**自己标记**的 TextDisplay。它会清理自己创建的，但不会去动其他插件的悬浮实体。所以如果那里已经有别的插件放的东西，两边可能同时显示。

### 为什么 `/menu` 里没有挂机池？

菜单里找不到挂机池入口。

这个问题的答案通常是**设计如此**：

1. **`afk-pool.enabled` 是 `true` 吗？** 默认是 `false`。
2. **`afk-pool.position-configured` 是 `true` 吗？** 两把锁必须都开。
3. **菜单的自动布局会隐藏关闭的模块。** 所以"看不到按钮"本身不是故障，它就是设计的行为——NekoCore 不会给你一个点了没反应的灰色按钮。

**为什么要有两把锁：** 坐标是最容易出事的东西。如果只有 `enabled` 一把锁，一个手快的管理员打开功能、坐标还没填，全服玩家点一下就会被送到 `x: 0.5, y: 64.0, z: 0.5`。两把锁的意思是：插件永远不会用占位坐标传送任何人。

**所以流程是：** 建好水池 → 读精确坐标 → 填进 `teleport` → 两把锁都开 → `reload` → 入口出现。

**如果两把锁都开了还是看不到：** 检查 `world` 字段的世界是否已加载。

配置细节见[配方手册的挂机池一节](RECIPES.md#我想做挂机池)。

### 为什么改了 config 没生效？

改了 `config.yml`，游戏里没有任何变化。

1. **你执行 `reload` 了吗？** `config check` **只验证，不应用任何改动**——这是它存在的意义。改完想生效必须跑 `/nekocore reload`。这两个命令的区别值得记住：

   | | 做什么 |
   | --- | --- |
   | `config check` | 只验证，什么都不改 |
   | `reload` | 验证通过后整体切换 |

2. **`reload` 是不是悄悄失败了？** 重载失败的时候服务器**继续使用旧配置**跑着，玩家完全感知不到——这是保护机制，但意味着你必须看返回消息。失败时会告诉你错在哪个 YAML 路径、期望什么类型或范围。Material 拼错还会给相近名称的建议。

3. **这个改动是不是 reload 覆盖不到的？** 这些必须完整重启：
   - 更换 JAR
   - 改 `database.filename`
   - 加入或更换 MMDB 文件
   - 安装新的第三方插件
   - 世界插件的变更

4. **你改的是哪个文件？** `config.yml` 管行为，`messages.yml` 管文字。改错了文件自然不会有效果。

5. **服务器是不是在自动布局下把入口藏了？** 改了 `enabled` 之后入口的**出现和消失**是正常行为，不是"没生效"。

**一个排查技巧：** 如果你不确定配置有没有被接受，跑 `/nekocore config check`。它用的是和 `reload` 完全相同的验证逻辑，通过就说明配置文件本身没问题。

### 世界入口消失了？

`/menu` 里某个世界按钮不见了。

**按顺序排查：**

1. **那个世界的 `enabled` 是 `true` 吗？**
2. **世界名大小写完全一致吗？** `World` 和 `world` 在 Paper 眼里是两个不同的东西。
3. **世界真的加载了吗？** 在控制台执行 `worlds` 或者看启动日志确认。**NekoCore 不会创建世界**——世界得由 Multiverse 或别的插件先建好并加载。
4. **`survival.command` 的占位符完整吗？** 必须同时包含 `{player}` 和 `{world}`，否则整个重载会被拒绝。注意这里写的是不带 `/` 前缀的命令本身。
5. **没有 Multiverse 的话怎么办？** 已加载的**主世界**入口可以安全回退到 Paper 世界出生点，所以不需要 Multiverse。但**依赖命令路由的额外世界**就需要装 Multiverse 了。

**记住自动布局的语义：** 关闭或世界未加载的入口会**被隐藏**，剩下的按钮重新居中。所以"少了一个按钮"是插件在如实告诉你"这个功能现在不可用"。

### `/nekocore reload` 失败了？

控制台报了一条重载错误。

**先放宽心：服务器还在用旧的有效配置跑着。** 玩家那边完全感知不到，你也没有处于一个危险状态。

**然后：**

1. **读第一条报错。** 错误信息里会有 YAML 路径（例如 `store.products.bred.material`）、错误类型和期望的范围。**只看第一条就够了**——后面的错误经常是第一条的连锁反应。
2. **对照着修。** 常见的是：缩进用了 Tab、冒号后面少空格、Material 名字拼错、数值超出范围、世界名格式不对、占位符缺失。
3. **Material 拼错时找建议。** NekoCore 会给出相近名称的建议（"你是否想填……"），直接照着改。
4. **修完再跑 `/nekocore config check`。** 通过之后再 `reload`。
5. **不要反复执行 Bukkit 的 `/reload`。** 它和 NekoCore 的重载完全是两件事，用它只会让服务器进入更不稳定的状态。

**如果报错涉及 JAR、数据库文件名或依赖：** 完整重启，reload 处理不了这些。（MMDB 文件例外，`reload` 会重新打开它。）

**如果你想彻底确认配置文件本身是干净的：** `config check` 用的是同一套验证逻辑，它通过就说明语法和取值都没问题。

## 自动测试覆盖了什么，没覆盖什么

这一节想说得直白一点，因为它影响你怎么理解上面那些"保证"。

**自动测试覆盖到的：**

- 配置的解析、验证和升级路径；
- 数据库 schema 的迁移（包括从全空目录开始的 fresh install）；
- 商店和 Bag 的事务恢复语义；
- 每日任务的选择、进度和事件处理；
- 缺少可选组件时的降级行为（用模拟对象验证插件契约）；
- 命令的注册和权限映射。

**自动测试覆盖不到的：**

- 真实的 Paper 实体和 UI 行为；
- Citizens、Multiverse-Core、Multiverse-Inventories、WorldGuard 的真实共存；
- 与其他 TAB / NameTag / 聊天插件的显示所有权冲突；
- TextDisplay 在真实世界里的生成和清理；
- 玩家背包操作在真实断线、崩溃、满背包场景下的表现；
- 在高负载下关停服务器的行为；
- 从你自己的真实备份升级。

**这些不是"应该没问题"，而是"需要你在测试服上验证"的清单。** 详细的验证步骤见[发布验证](../../VERIFICATION.md)。

## 还是没解决？

按这个顺序试：

1. **把 `advanced.debug` 临时设成 `true`**，重启，看完整的异常信息。**问题解决后记得关回去**——它会输出很多平时不需要的东西。
2. **读[发布验证](../../VERIFICATION.md)**，看看你的场景是不是在"需要人工验证"的清单里。如果是，那问题可能不在配置上，而在于这台服务器本来就还没被验证过。
3. **如果要向别人求助**，先看[安全策略](../../SECURITY.md)——里面有怎么给数据库、IP 和玩家信息打码的说明。**不要直接把整个 `nekocore.db` 或者完整日志发到公开的地方。**
