# GeoIP：合法安装地区数据，以及隐私模型

[English](../en/GEOIP.md) | [返回 README](../../README.md)

NekoCore 可以把你服务器的 TAB 变得更有"社区感"一点——在玩家名字前面显示一个粗粒度的地区标签，比如 `[广东]` 或者 `[Japan]`。这样同城的人会更容易互相认出来。

但这个功能和别的功能不太一样：**它需要一份你必须自己去取得的数据文件，而且这份文件的使用受第三方条款约束。** 这一页把安装流程和隐私边界讲清楚。

---

## 三件事先说在前面

1. **NekoCore 的 JAR、源码仓库和 Release 里不包含任何 MMDB 文件。** 一个字节都没有。
2. **也不包含任何 MaxMind 的 license key 或账号凭据。**
3. **默认是关闭的。** `location-prefix.enabled` 出厂就是 `false`，你不主动打开它就不会有任何 IP 解析行为。

换句话说，这个功能是"你主动选择开启，并且自己准备好数据"的模式。这是有意设计的。

---

## 取得数据

去 [MaxMind 的 GeoLite2 官方页面](https://dev.maxmind.com/geoip/geolite2-free-geolocation-data/)，按他们当时的条款注册账号并下载数据库。

**要下 City 版，不是 Country 版。** 区别在于：

| 数据库 | 精度 |
| --- | --- |
| GeoLite2-**City** | 能到省级（中国省份显示就是靠它） |
| GeoLite2-Country | 只能到国家 |

如果你想让中国玩家看到自己所在的省份，必须用 City。数据库的格式说明见[官方 City/Country 二进制文档](https://dev.maxmind.com/geoip/docs/databases/city-and-country/city-binary/)。

**不要用不明来源的镜像。** 那些文件的来源、更新时间和完整性都无法核实，而且可能违反 MaxMind 的条款。这类文件会被读进你的服务器进程，来源不明的版本不值得冒这个险。

## 安装

### 步骤

1. **解开压缩包。** MaxMind 给你的是 `.tar.gz`，里面才是 `.mmdb`。**直接把压缩包改名放进去是读不出来的**——这是最常踩的一个坑。

2. **放好文件。** 把 `.mmdb` 重命名为 `GeoLite2-City.mmdb`，放到：

   ```text
   plugins/NekoCore/GeoLite2-City.mmdb
   ```

   注意是 `plugins/NekoCore/`，**和 `config.yml` 同一个目录**。不是 `plugins/` 根目录。

   放文件本身可以在服务器运行时做，不会有影响——真正的生效发生在下一步。

3. **改配置：**

   ```yaml
   location-prefix:
     enabled: true
     database-file: GeoLite2-City.mmdb
     cache-session: true
     show-china-province: true
     show-foreign-country: true
     hide-unknown: true
   tab:
     enabled: true
     show-location-prefix: true
     refresh-seconds: 1
   ```

4. **让它生效。** `/nekocore reload` 就够了——重载会重新打开 MMDB 文件并清空会话缓存，所以**新放进去的数据文件在重载后就会开始工作**。如果你更习惯完整重启，那当然也可以。

5. **验证：** 运行 `/nekocore status` 看 GeoIP 的状态，同时扫一眼启动日志——正常的话不会有大段堆栈。

### 怎么确认成功了

进游戏看 TAB，自己名字前面应该出现类似这样的前缀：

```text
[广东] 你的名字
[日本] 另一个玩家
```

前缀的样式在 `messages.yml` 的 `location-prefix-format` 里可以改。

### 配置项的含义

| 字段 | 作用 |
| --- | --- |
| `enabled` | 总开关。默认 `false` |
| `database-file` | MMDB 文件名，相对于 `plugins/NekoCore/`。大小写敏感 |
| `cache-session` | 会话级缓存。解析过的结果在本次运行内复用，停服后消失 |
| `show-china-province` | 中国玩家显示到省份 |
| `show-foreign-country` | 外国玩家显示到国家 |
| `hide-unknown` | 保留字段。解析不出来时不显示地区由格式化逻辑天然保证 |

`tab.show-location-prefix` 是一个**独立的全局开关**，控制 TAB 里显不显示地区。它和玩家的个人隐私开关是两套东西。

### ⚠ `cache-session: false` 不是"每次都实时查询"

这一条必须专门说，因为它反直觉而且后果严重。

把 `cache-session` 设成 `false`，**不会**让插件每次去查一遍数据库——它会让解析结果**完全不写入缓存**。而下游读取地区时读的是缓存。

结果是：**所有玩家都不会显示地区。**

所以除非你在排查一个非常具体的问题并且清楚自己在做什么，**保持 `cache-session: true`**。

### 关于 `hide-unknown`

这个字段会被正常解析和保存，但当前版本里**主代码没有引用它**——它是一个保留字段。

"解析不出来的时候不显示地区"这个行为是**默认就有的**，由地区格式化逻辑在拿不到结果时返回空串自然实现，不依赖这个开关。所以不管它设成 `true` 还是 `false`，效果都一样。

写在文档里是为了让你知道：改了它没反应是正常的，不用怀疑是配置没生效。

## 隐私模型

这部分是认真的，因为它涉及真实玩家的个人信息。

### NekoCore 做什么

- **不把完整 IP 写进数据库。** 数据库里根本没有存 IP 的字段。
- **不向聊天或 TAB 显示完整 IP。** 只显示省份或国家级别的粗粒度结果。
- **NameTag 不显示地区。** 玩家头顶的名字里从来不会有地区信息，这一项不需要你额外关。
- **会话缓存只缓存解析结果**，缓存的也是粗粒度地区而不是 IP，而且停服就消失。

### 玩家自己的控制权

玩家可以在 `/menu` 里切换"显示网络地区"这个开关。

关掉之后，**他们自己的地区就不会显示**。这是一个玩家级别的选择，不受全局配置强制。

**为什么要保留这个开关：** 因为地区信息即使粗粒度，也是玩家的个人信息。有些人就是不想让自己的位置被任何人推断出来——哪怕只是一个省。给他们一个开关，比替他们决定要尊重得多。

### 两层开关的关系

| 控制层 | 位置 | 作用范围 |
| --- | --- | --- |
| 全局 | `tab.show-location-prefix` | 整个服务器的 TAB 显不显示地区 |
| 个人 | `/menu` 里的隐私开关 | 单个玩家自己的地区显不显示 |

**两个都开的时候才会显示。** 所以你可以全局开着，让愿意分享的玩家显示、不愿意的玩家自己关掉——这是推荐的做法。

### 你需要自己判断的部分

- **你所在地区的法律。** 显示玩家的地理位置信息在某些司法管辖区有额外的合规要求。这一条 NekoCore 没法替你判断。
- **你的服务器隐私政策。** 如果你有公开的隐私说明，应该提到会处理粗粒度地区信息。
- **MaxMind 的许可条款。** GeoLite2 数据的使用受他们的条款约束，包括署名和再分发方面的要求。注册的时候请认真读一遍。
- **告知玩家。** 说一句"TAB 里会显示粗略的地区"，比让玩家自己发现要好。

### ⚠ 不要公开的东西

| 不要公开 | 为什么 |
| --- | --- |
| `GeoLite2-City.mmdb` 文件 | 受 MaxMind 许可约束，不要提交到 Git、不要放进公开整合包 |
| MaxMind 账号的 license key | 那是你的账号凭据 |
| 真实的服务器日志里的 IP | 日志可能包含玩家连接信息 |
| 数据库文件 | 里面有玩家 UUID 和游戏数据 |

如果你在帮别人排查问题，这些都要打码。具体做法见[安全策略](../../SECURITY.md)。

## 不显示的时候怎么查

按这个顺序过一遍，前面几步能解决绝大多数情况：

1. **`location-prefix.enabled` 打开了吗？** 默认 `false`。
2. **重载或重启过了吗？** 放了文件、改了配置之后，需要 `/nekocore reload`（或者完整重启）才会读取。**光把文件拷进去不会自动生效。**
3. **文件位置对吗？** 必须是 `plugins/NekoCore/GeoLite2-City.mmdb`。
4. **文件名大小写一致吗？** `database-file` 里写的和磁盘上的必须完全一样。Linux 上尤其注意。
5. **下的是 City 版吗？** Country 版没有省级数据。
6. **解压了吗？** `.mmdb` 得从 `.tar.gz` 里解出来。
7. **文件完整吗？** 下载中断会产生一个截断的文件，读取会失败。
8. **玩家自己关了隐私开关吗？** 这是功能不是 bug。
9. **`tab.show-location-prefix` 是 `true` 吗？**
10. **`cache-session` 是不是被改成 `false` 了？** 改成 `false` 会让全服都不显示地区。改回 `true`。
11. **有别的 TAB 插件在覆盖吗？** 两个插件争同一块显示区域时，谁后写谁赢。

### 需要看详细错误时

缺失或损坏的 MMDB **默认只会安静地禁用 GeoIP**，不会在日志里刷一大段异常堆栈。这是为了不吓到普通管理员——但代价是你需要主动打开详细输出才能看到细节。

临时设置：

```yaml
advanced:
  debug: true
```

改完 `reload`（或重启），就能看到完整的异常信息。**排查完之后记得关回去。**
